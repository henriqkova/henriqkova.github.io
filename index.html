Arquitetura

Como meus pipelines funcionam

Uso o mesmo esqueleto e adapto a cada fonte de dados. Cada etapa tem uma responsabilidade e, se falhar, eu fico sabendo.

Por que separar o adapter

Cada fonte tem seu jeito de paginar, limitar e apagar registros. Isolo isso num adapter e as regras de negócio ficam iguais para qualquer ERP.

Por que a trava de paridade

Um painel bonito com número errado é pior que nenhum. Meu script compara o resultado com o relatório do sistema e bloqueia a publicação se divergir.

Por que container com cron

Agendamento de CI atrasa e tarefa local depende de máquina ligada. Por isso rodo tudo em container, onde o horário é previsível e eu acompanho cada execução.

Problemas que resolvi

São projetos reais que fiz na BGP, sem nomes de clientes. O foco é o problema técnico e como eu resolvi.

01 · Consolidação · 5 contas

API que só aceita uma chamada por vez

Precisei consolidar cinco empresas no mesmo ERP, sem paralelismo por chave e com paginação que para em silêncio.

Node.js · cache incremental · Docker
Ver detalhes

Implementei cache incremental em volume, carga completa só aos domingos e conferência pelo total de registros. Todo o cálculo foi para o servidor porque o navegador do celular não aguentava.

Paridade com o extrato do sistema e saldo conferido banco a banco.

02 · Autenticação

Login com código enviado por e-mail

O sistema passou a exigir um código por e-mail a cada acesso, o que quebrava a automação.

Playwright · Microsoft Graph · Node.js
Ver detalhes

Registrei um app no Azure e o robô lê o código pela Microsoft Graph, completa o login no Playwright e segue sozinho.

Atualização automática restabelecida sem intervenção humana.

03 · Rede · proxy

API acessível só por IP liberado

Precisei ler uma API que só respondia a IP liberado e não trazia a categoria da despesa.

Proxy · Docker · parsing
Ver detalhes

Coloquei um proxy num container com IP fixo e adaptei a leitura do razão contábil em partidas dobradas. A categoria da despesa não vinha na API, então passei a extraí-la do histórico de cada título.

Caixa pela data de crédito e receita por plano.

04 · Migração

Regras do Power BI levadas para código

Precisei migrar relatórios .pbix para a web sem perder regra nenhuma.

Power BI · DAX · ADOMD / TOM
Ver detalhes

Li o modelo direto pelo ADOMD e TOM, extraí as medidas DAX e as reescrevi em JavaScript, conferindo os totais mês a mês com o relatório original.

Também troquei fontes de .pbix em lote por automação.

05 · Marketplaces

Margem real por pedido

Reconstruí a comissão a partir do relatório de liquidação, em que o layout muda por conta.

APIs de marketplace · OAuth · Node.js
Ver detalhes

Como a API só guarda 12 meses, o histórico passou a ser preservado do meu lado. Também cuidei do OAuth com refresh token rotativo.

Conciliação de repasse e margem por pedido.

Do servidor local para a nuvem

Nada mais depende de máquina ligada.
